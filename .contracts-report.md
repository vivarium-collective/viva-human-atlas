## What changed

### 1. Named bigraph-schema types (new `viva_human_atlas/types.py`)

```python
WORKSPACE_TYPES = {
    "reference_organ": {
        "ref_organ_id": "string", "organ": "string", "uberon": "string",
        "sex": "maybe[string]", "asset_url": "maybe[string]",
    },
    "cell_type_term": {"cl": "string", "count": "integer"},
    "anatomical_term": {"term": "string", "count": "integer"},
    "matched_organ": {"organ": "string", "uberon": "maybe[string]"},
    "biomodel_do": {
        "biomodel_id": "string", "name": "string",
        "organs": "list[matched_organ]", "provenance": "tree",
    },
    "organ_to_models": "map[list[string]]",
}
```

`register_workspace_types(core)` is wired into BOTH
`viva_human_atlas/__init__.py::register_types` (after delegating to
`pbg_biomodels.register_types`) and `viva_human_atlas/core.py::build_core()`
(after `register_biomodels_types(core)`), matching the `pbg_biomodels`
`TYPES_DICT` + `register_types(core)` convention (`core.register_types(dict)`).

### 2. Step ports retyped

| Step | Port | Before | After |
|---|---|---|---|
| `HRAReferenceOrgansStep` | `reference_organs` (out) | `list[tree]` | `list[reference_organ]` |
| `HRACellTypesStep` | `cell_types` (out) | `list[tree]` | `list[cell_type_term]` |
| `HRAAnatomicalStructuresStep` | `anatomical_structures` (out) | `list[tree]` | `list[anatomical_term]` |
| `BiomodelDOCatalogStep` | `biomodel_dos` (out) | `list[tree]` | `list[biomodel_do]` |
| `BiomodelDOCatalogStep` | `organ_to_models` (out) | `tree` | `organ_to_models` (`map[list[string]]`) |
| `BioModelsSearchStep` | `model_ids` (out) | `list[string]` | unchanged (already meaningful) — got description/contract only |

No field renames were needed — the Steps' hand-built dicts already matched
the field names used in the new types (`ref_organ_id`/`organ`/`uberon`/
`sex`/`asset_url`, `cl`/`count`, `term`/`count`, `biomodel_id`/`name`/
`organs`/`provenance`, `organ`/`uberon`).

**One real behavioral fix required by the retype**: `organ_to_models`'s new
`map[list[string]]` port type has different `apply` semantics than the
previous bare `tree` — `bigraph_schema.methods.apply`'s `Map` handler only
updates keys *already present* in state; brand-new keys need the `_add`
sentinel (unlike `Tree`, which free-adds new keys). `BiomodelDOCatalogStep.update()`
now returns `{"organ_to_models": {"_add": catalog["organ_to_models"]}}`
(same convention `viva_munk`'s `GrowDivide` uses for adding new agents).
Without this fix, `organ_to_models` came back empty in the offline test —
caught by the existing test suite, not something I discovered separately.

### 3. Descriptions + per-port contracts

Confirmed convention in `bigraph_schema/edge.py`: `description` class attr +
`describe()` (falls back to docstring), plus a `contract` class attr
(`ProcessContract`-shaped dict) with per-port `inputs`/`outputs` description
maps, resolved via `bigraph_schema.contract.resolve_contract`. Real working
example found in production: `viva_munk/processes/pressure.py` sets
`Pressure.contract = {...}` as a **module-level attribute assignment after
the class body**. All 5 target Steps now follow this exact pattern:
`description` class attr (used by `describe()`) + a post-class-body
`<Step>.contract = {"summary": ..., "outputs": {port: "..."}, ...}` (plus
`config` doc for `BioModelsSearchStep`, `assumptions` for
`BiomodelDOCatalogStep`).

### 4. Composite generators — dotted addresses (real gap found + fixed)

The 4 wired generators (`hra_steps.py`, `biomodel_do_composite.py`) declared
Step addresses as **bare registry names** (`"local:HRAReferenceOrgansStep"`).
`vivarium_workbench/lib/process_docs.py::_doc_for_address` only resolves a
`description`/`docstring` for a **dotted** `local:<module>.<Class>` address
(bare names need a live-built core, which the static/publish resolve path
doesn't have) — `pbg_biomodels`'s own composites already use the dotted
form (`local:pbg_biomodels.steps.load_biomodel.LoadBiomodelStep`). Changed
all 4 Step addresses to the dotted form
(`local:viva_human_atlas.hra_api.HRAReferenceOrgansStep`, etc.) so the
Explorer actually resolves `doc`/`_contract` for these nodes instead of
silently skipping them. `build_core()` already registers both the dotted
path and the bare class name (`core.register_link(dotted, cls)` +
`core.register_link(cls.__name__, cls)`), so this didn't require any
registry changes — just fixing the address strings the generators wire up.
`local:RAMEmitter` (bare) is left as-is — that's the universal convention
across `pbg_biomodels` too (RAMEmitter is a base-core link, always
resolvable without the workspace's own core).

## Concerns / notes

- `BioModelsSearchStep` is defined but not wired into any composite
  generator (`glucose_regulation.py` calls the bare `search_biomodels`
  function directly, not the Step). It got description/contract per the
  task, but there is no composite to show its ports in the Explorer — that
  pre-dates this change and is out of scope to fix (would mean adding a new
  generator, not asked for).

  type` / `type(name, bases, dict, **kwds) -> a new type` (Python's builtin
  `type` docstring) for `local:RAMEmitter` — a pre-existing
  `vivarium-workbench`/`env_worker` quirk unrelated to this change (RAMEmitter
  itself was never touched), left as-is.
- `pbg_biomodels.two_tier` (missing `pyarrow`) and
  `pbg_emitters.parquet_emitter` (missing `duckdb`) discovery warnings are
  pre-existing environment gaps, not introduced by this change (present in
  the very first, pre-change test run's warnings too).
